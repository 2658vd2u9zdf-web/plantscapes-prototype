# v0.3 operational runtime implementation

## Architecture

The v0.3 CSV, location contract, scoring JSON, derivation ledger, Python evaluator and canonical result files are authoritative and remain unmodified. `python dataset/build_runtime_v0_3.py` uses the preserved CSV decoder to emit one deterministic `website/data/operational-v0.3.generated.js` bundle. It retains all profile fields and trace objects, including field-level real/operational resolutions, origins, confidence, claim IDs, unresolved safety status and synthetic/inferred derivations.

The browser and Node server load the same bundle and `website/suitability-v0.3.js`. The JavaScript evaluator ports the Python matrices, weighted components, H01–H11 gates, caps, score classes, confidence formula, placement diagnostics and single-species capacity semantics. `website/runtime-adapter-v0.3.js` converts UI values and plans into the contract and sends explicit operational height, spread, spacing, layer, role, support, vigour and thorn state to the design engines. Candidate ranking follows the explicit `ranking_stages` in the rules file (v0.3.1): capped score, raw score, native-evidence tier, design preference, confidence and stable fixture ID (code-point order); see `RECOMMENDER-SYSTEM-AUDIT.md`. The browser never ranks by fixture position or silently asserts safety.

The website keeps taxonomy-only catalogue search separate from operational candidates. `website/data/demo-data.js` remains loaded solely for city/place presets. Paths, beds, water, exclusion polygons, neighbourhood distances, tree crowns and community recipes are still handled by the placement engines. Community recipes retain editable plant-count percentages and whole-site estimated quantities. The AI server re-evaluates every allowed and proposed plant against its own v0.3 data, supplied project/zone conditions and the matched mapped bed. AI cannot add taxa or override those checks by changing browser `allowedIds`.

## Input and output limits

The UI exposes maintenance, public access and harvest, sightlines, climbing support, active vigour control, zone path-edge context, clear dimensions, visibility height and mapped support length. Empty required geometry remains `unknown`. City suggestions carry `synthetic_fallback` field origins. The adapter keeps a zone at demo source confidence while any defaulted site field remains synthetic, even if a user changes the source label. Drawing a bed supplies geometry for placement screening; polygon/path/asset checks remain separate.

All 60 records remain `production_eligible=false`. Results can be conditional demonstration candidates with low evidence confidence. An unknown policy value is never rendered as an absence, clearance or native claim. Expanded cards and CSV export show the score class, raw/capped scores, confidence, non-passed gates, warnings and field origins. Synthetic SPACE-01 spacing and resulting quantities are approximate. Public harvesting is never approved. Climbers are not placed in generic beds or communities because mapped support placement is not implemented. A square bounding screen can also conservatively reject a shape that might fit with a tailored layout, and a passing square screen does not prove clearance in a concave bed.

## Test record

Before implementation, `tests/communities.mjs` passed. `tests/smoke.mjs` failed on an outdated paths-required assertion. `tests/ai-server.mjs` could not connect to localhost inside the sandbox. Playwright tests could not resolve Playwright without the desktop bundled `NODE_PATH`; after resolving it, the sandbox prevented Edge startup. `dataset/validate_demo_matching_v0_3.py` failed on a pre-existing protected v0.2 file hash. Location validation reported exactly three authoritative dependency hash errors with 4,455 other checks passing.

After implementation, `tests/suitability-v0.3.mjs` compares every result field for all 180 canonical plant-zone evaluations and passes. `tests/runtime-integration-v0.3.mjs` checks 60 stable records, ranking, unknown preservation, source certainty and direct server AI rejection. Updated `tests/smoke.mjs` and `tests/communities.mjs` use operational v0.3 records and pass with optional paths, geometry, quantity, overlap and deterministic-placement checks. `tests/ai-server.mjs` passes with a mocked provider when localhost access is allowed. The four browser tests cover palette cards, CSV, pathless and path plans, editable and undoable community recipes, schematic/seasonal views, imported images, render-scene export, browser AI context and camera layout. They make no paid provider call.

The old browser scripts initially referred to selectors and path-first flow from a different UI revision. They were updated to the current v0.3 workflow. The missing location control, hidden evidence/recipe/export controls and associated script errors were repaired. Validation hash baselines were not rebuilt and must not be reported as passing.

An attempted browser POST of generated context to `/api/feedback` was rejected by automatic approval review because that endpoint could call a paid provider if AI were enabled. This check was removed. Direct `validateContext`/`validateProposal` calls and the mocked AI-server test cover server validation without sending that context externally.
